# BEK264_rating_bot

Telegram-бот с журналом взаимных оценок группы. Меню и оценки находятся в `bot.py`, обмен с Telegram в `run.py`, выбор серверного журнала в `main.py`.

## Подключение работающего бота на Altare

1. Скачай [auto_update.py](https://github.com/spyCHka/BEK264_rating_bot/releases/latest/download/auto_update.py). В Altare открой сервер BEK264_rating_bot → **Файлы** и загрузи его рядом с существующим `main.py`.
2. В разделе **Запуск / Startup** выбери `auto_update.py` как стартовый Python-файл. Если редактируется целая команда, укажи `/usr/local/bin/python /home/container/auto_update.py`.
3. Нажми **Перезапустить** один раз. В консоли появятся «Автообновление запущено» и, после получения релиза, «Запущена сборка …». Отправь боту `/table` в Telegram и проверь журнал.

Запуск использует прежние `data/` и токен Telegram. Исходный `main.py` служит резервной точкой входа до первого принятого обновления. Чтобы вернуться к нему вручную, выбери его в настройках запуска и перезапусти контейнер.

## Обновления

Отправь правки кода в ветку `main`. GitHub Actions собирает и проверяет бота, затем публикует сборку в [Releases](https://github.com/spyCHka/BEK264_rating_bot/releases). Бот проверяет наличие новой сборки каждые две минуты. После загрузки и сверки SHA-256 он останавливает прежний процесс и запускает новый. Если новый процесс завершается в первые 12 секунд, запускается предыдущая версия. При недоступности GitHub продолжается работа локальной копии. Перезапуск контейнера требуется при первоначальном подключении или изменении самой программы `auto_update.py`. Правки одного README пропускают выпуск.

Для возврата предыдущего кода отмени нужный коммит через `git revert` и отправь изменения в `main`. Откат кода сам по себе не отменяет изменений схемы базы.
